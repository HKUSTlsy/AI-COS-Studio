# AI COS Studio

个人使用的本地 AI COS 创作工作台。Studio 既可通过 Codex App Server 使用当前 Codex 登录状态和内置 imagegen，也可准备 ChatGPT 网页手动生图交接；不保存 API Key、Cookie 或 Token，不使用云数据库，也不部署上线。

## 环境要求

- Node.js 22.13 或以上，npm。
- Codex 桌面应用及其已有登录状态，用于内置生成；手动网页交接由用户自行操作。
- VSC Prompt 创作需要另行合法安装 README 中所述技能；这些第三方技能不随本项目分发。
- 可选环境变量见 [.env.example](.env.example)。应用直接读取启动进程的环境变量，不自动载入 `.env`；可用 `export` 设置。

## 启动

```bash
npm ci
npm run dev
```

打开 `http://127.0.0.1:4317`。也可以运行：

```bash
.agents/skills/ai-cos/scripts/ai-cosctl open
```

工作台绑定 `127.0.0.1:4317`，本地 API 绑定 `127.0.0.1:4318`。API 会优先启动 Codex 桌面应用内置的可执行文件；无需依赖 Homebrew Codex。

## 四步创作流程

1. 上传动漫角色主图和可选补充图，点击“确认并自动解析”。后台临时 Codex 会话会读取参考图并自动写回角色还原卡。
2. 查看和编辑角色卡。被用户修改的字段会标记为 `user_confirmed`；未修改字段保留 `observed / inferred`。
3. 选择脸模、摄影风格、目标画幅（跟随主图、1:1、4:3、3:4、16:9、9:16）和生成方式，确认后生成一张高忠实基准图。画幅只是原生构图目标，不后期裁切、拉伸或补边；归档后会记录实际像素尺寸。
4. “后期创作”包含三个并列入口：
   - “单项调整”从任意版本继续，只改动作、服饰、背景、身材比例、妆容、发型/发饰、镜头/光线或其他单项细节。输出使用非覆盖命名 `adjustment-vNNN.<ext>`。
   - “随机重拍”从变量池生成 1–4 条不同方案。
   - “系列写真”先拆解 1–8 张写真参考的共同视觉 DNA、布光与成像机制，再生成 1–4 个可编辑新分镜。随机重拍和系列写真都在确认 Prompt 后才调用图片工具，输出使用 `reshoot-vNNN.<ext>`。

四个步骤可回退。修改参考图、角色卡、脸模或风格时会创建新版本；旧配置和旧图片不会删除。失败或中断只会记录真实原因，必须由用户手动重试。输入变更后不能重试旧执行，需要重新确认本阶段。分支创作使用源图对应的历史设定，不混用后来修改的角色卡。

## VSC Prompt 创作

顶部新增独立的 **Prompt 创作**，不要求先创建基准图：

- 输入照片需求，选择角色名 / 文字、已授权脸模，或通过面部验收的已有单人版本；支持 1–4 人混合来源。各人单独设置站位、成年确认及原装 COS / 角色演绎 / 自由写真范围。
- VSC 先输出 1–4 条完整自然语言 Prompt。可逐条编辑、收藏完整原文，或填写反馈只修改勾选的方案；其他方案不变。不会自动拆成模块或方案包。
- 保存编辑后查看最终生图 Prompt，明确确认才调用内置 imagegen 或准备网页交接。每组一张，逐张非覆盖归档；部分失败不抹掉成功结果，也不自动重试。
- 角色基准、后期版本与脸模卡片都有“用 VSC 创作”快捷入口。Prompt 创作记录可从本页或作品历史恢复，旧作品四步流程与原多人合影入口保留。

依赖本机已安装的 VSC 技能，不在源码中复制第三方全文、不自动联网安装更新。自动路由覆盖角色抓拍、生活人像、夏日朋友视角与风格探索；东方幻想须显式选择，视频与 Eagle 不会自动执行。保存本轮技能路径与 SHA-256；若所选技能变动，须新建任务。`AI_COS_VSC_ROOT` 可指定已安装技能的父目录，默认读取当前 Codex skills 目录。

创作方向中的「色狼偷拍感（虚构摆拍）」对应 [VoxCat 的角色摄影 Skill](https://x.com/VoxcatAI/status/2097511865857507750)，即原菜单的「角色自然抓拍」。继续使用已安装的 `character-candid-photography`，不重复安装、不改变旧任务的技能 ID。强调前景遮挡、长焦/手机快拍与发现镜头的瞬间，仅用于成年角色、知情同意的虚构摆拍；人数、造型权限和输出数量仍以 Studio 中的选择为准。

数据保存在 `local-data/prompts/creations.json`；文字阶段 `prompt_compose` 与图片阶段 `prompt_render` 共用已有单并发队列，执行目标为 `prompt_creation`，不伪造必须有动漫参考的 GenerationJob。`GET /api/vsc/capabilities` 可检查安装状态。新命令为 `show-creation`、`claim-creation`、`apply-creation-drafts`、`attach-creation-output`、`fail-creation-variant` 与 `fail-creation`；机器写回均要求 `--creation` 和 `--run`。

## 管理与恢复

- 第四步提供版本对比、收藏、采用标记、独立作品封面和成套导出。设为封面不会改变生成源图。
- 任务记录允许取消排队、停止执行、取消网页交接；失败分镜可单独建立新草稿，再由用户确认生成。系列 Prompt 可返回企划修改后重新编译。
- 脸模、Prompt 和摄影包支持搜索、版本历史以及归档/恢复；归档不删除历史引用。所有上传脸模均需确认使用授权。
- 未提交的主要文字草稿保存在本机浏览器；图片不存入浏览器草稿，离开前会提醒重新选择。
- 历史页可下载全库备份，建议在没有任务运行或素材修改时使用；单个作品可连同原图、输入快照和 Prompt 成套导出。备份不会自动恢复或覆盖现有资料。

## 生成方式

- `Codex 内置生成`：进入本地单并发 Codex 队列，由项目 `$ai-cos` Skill 调用内置 imagegen 并自动归档。
- `ChatGPT 网页交接`：普通任务在本机生成 `prompt.txt`、`manifest.json` 和按用途编号的参考图；创意重拍会生成共享素材及 `prompt-01.txt` 至 `prompt-04.txt`。用户手动上传、生成、下载，再把结果导回对应槽位；可以完整导回，也可以明确以部分结果结束批次。

生成方式会记住上次选择，首次默认为 Codex 内置生成。网页交接不读取 ChatGPT 的 DOM、Cookie、Token 或网络请求，也不会自动上传、点击生成或下载。如果输入在等待期间变更，该交接会失效并需重新准备。

## 自动桥接

- 每个解析、内置基准生成、内置调整、摄影方案包解析、系列写真参考拆解、创意重拍或 Prompt 拆分任务使用 `ephemeral: true` 的隔离线程，不在侧边栏留下新任务。网页交接不进入此队列。
- 每条任务显式附带项目内 `$ai-cos` Skill，不覆盖用户的默认模型设置。
- Codex 只拥有当前项目的 `workspaceWrite` 权限，Shell 网络关闭；图片仍由内置 imagegen 处理。
- 队列单并发执行并使用原子 claim 防重。服务重启时，运行中的任务标为 `interrupted`，不会自动重试。
- 机器命令必须携带 `--run <runId>`。取消后迟到的领取、失败记录和输出归档不能修改新的执行。
- 本地 API 校验 Host、网页来源和临时会话令牌；令牌只用于保护本机写请求，不是 OpenAI 登录令牌或 API Key。
- 可通过 `GET http://127.0.0.1:4318/api/bridge/health` 查看连接、队列和当前任务。

## Prompt 库

新生成的 Prompt 使用[简洁摄影编排](docs/concise-prompts.md)：画面与动作在前，取景、光线和必要约束在后，减少重复的真人质感说明。完整收藏原文和历史 Prompt 不自动改写，内置短模块保留版本记录。

默认入口是“完整 Prompt”：粘贴最多 30,000 字符并原文收藏，不调用模型、不拆分或改写，编辑时保留最初原文和旧版本。第 4 步的“完整 Prompt”可整套使用收藏：选择源图和服装策略 → Codex 提出准确原文片段的最小替换及原因 → 用户编辑、排除并确认适配 → 审核完整生图 Prompt → 确认生成一张。未修改的原文、顺序及摄影配合关系保持不变，完整收藏与适配快照随输出保存。

需要组合复用时，可从收藏显式“另存为模块”或“提取随机方案包”，不改变原收藏；旧拆分记录也可以另存为完整收藏。原有 Prompt 模块支持 8 类：摄影风格、视角/景别、场景/灯光、动作、服饰、身材比例、妆容、发型/发饰。

- “自动拆分”可粘贴最多 30,000 字符的完整 Prompt。Codex 只会按原文实际存在的分类生成待确认草稿，不调用 imagegen。
- 草稿可编辑、取消导入或人工重试。点击“确认添加”后才会原子写入正式模块库。
- “分项添加”与现有模块编辑、版本化保留不变。

Prompt 库另有“摄影方案包”标签页：

- 可粘贴完整 Skill / 摄影资料，或导入公开 GitHub 仓库根、`tree`、`blob`、`raw` 链接。目录链接会定位 `SKILL.md`；系列企划可读取同仓库、同 revision 的关联 Markdown、`manifest.json` 和 `LICENSE`。只允许 GitHub 官方公开 HTTPS 地址，最多 8 个文件、10 秒、合计 100 KiB。
- Vibeshot 抓拍和 Nuyoah 系列写真以两个快捷来源卡片提供。第三方完整原文不会写进 Studio 源码，只存于被 Git 忽略的本机目录，并保留逐文件 SHA-256、总哈希、revision、导入时间、许可与授权备注。
- Codex 把内容解析成全局风格、避免项，以及表情、服装、场景、动作瞬间、景别、焦段、机位、构图、前景、光线、色彩、摄影状态十二个变量池。默认人物、肤色、身材和身份设定会被排除。
- 系列企划包保存视觉 DNA、成像机制、画面信息层级、世界空间布光拓扑、人物事件因果、返工重置和七项质量门禁。写真参考人物永远不承担身份；身份和角色设定只来自脸模、角色卡与干净源图。
- 用户确认后才正式入库。后续编辑创建新版本；旧重拍批次保存方案快照，不会被新版本改变。

单人创意重拍可选“原装重拍”或“角色演绎”。默认原装重拍保留 COS 服装；角色演绎需确认角色为成年人并授权换装，可采用模板服装、填写服装要求或上传服装专用参考图，同时仍锁定脸部与身体身份、妆容、发色发型、头部发饰和瞳色。道具可单独选择保留原标志性道具或按摄影方案。运行策略独立于摄影包默认锁；旧任务与基准还原规则不变。

摄影包明确启用抓拍遮挡规则时，随机抓拍才允许方案指定的局部出画和前景遮挡；系列写真为每个分镜绑定一张主摄影参考和最多两张同布光辅助参考，并保存七项质量检查。网页版交接会逐张列出不同的输入顺序。系列返工重新使用干净源图、原始写真参考和反馈，上一张生成图只作为诊断记录。

## 本地数据

私人素材和任务状态位于被 Git 忽略的 `local-data/`：

```text
local-data/
├── faces/
├── characters/
├── prompts/
├── jobs/
├── outputs/
├── backups/
└── runtime/
```

数据会自动迁移到 schema v5：旧任务的第一张候选图成为基准图，旧精修成为调整版本，其余候选保留在兼容历史区；v4 摄影包和重拍批次迁移为 `variable_pool`，系列写真字段初始化为空。旧图片、Prompt、版本号和路径保持不变，原有生成记录标记为 `built-in-imagegen`。
