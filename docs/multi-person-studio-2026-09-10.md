# 夏日摄影包与多人合影

## 已接入

第 4 步增加“多人合影”，保留单项调整、随机重拍和系列写真。首版支持
2–4 位明确成年人物，各自从不同作品选择已验收的单人 COS 输出。
角色 A 来自当前作品，B/C/D 来自其他作品。每次确认仅生成一张照片。

选择独立人物和位置 → 确认一个共同事件与一种成像介质 → 准备可编辑
Prompt → 用户确认后进入内置队列或 ChatGPT 手动交接。可追加一张只提供
共享环境、构图和光线的场景图，PNG/JPG/WEBP，最多 20 MB。

服装逐人默认锁定；转译角色主题泳装需要该人的成年确认和换装确认。
身体身份、面部、妆容、发型发饰和瞳色不随换装解锁。不继承资料中的
默认性别/肤色/身材、自动成年化或摄影者身体入镜。发现参考人物年龄
不明或不符合授权时停止，不改写年龄继续生成。

## 数据和执行

- 新接口：`POST /api/jobs/:id/reshoots/multi-person`，只创建草稿，不执行生图。
- 复用现有 draft PATCH、confirm、cancel、recover、逐 variant 归档接口。
- `mode: multi_person`、`multiPerson` 快照是现有 schema v5 的增量字段；旧数据不重写。
- 快照保存每人的 job/output ID、角色卡、脸模、源图、位置、服装权限，以及共享事件、相机介质和可选场景参考。
- 顺序为 N 张独立人物源图 → 可选场景参考 → 按人物隔离的细节参考。
  `multiPersonAssets` 同时供 Prompt 编号、CLI 和网页清单使用。
- 延续 `reshoot-vNNN` 非覆盖归档、真实尺寸记录、最大原生尺寸请求和网页“阿茶”署名。
- 最大尺寸仍是 Prompt 请求，不是隐藏 API 参数或实际像素保证。
- 历史合影可查看、收藏、采用和导出；“载入原始人物，再拍一张”重新准备原始独立人物。
  合影不能直接进入单人调整/随机/系列流程，以免漏掉其他人的约束。
