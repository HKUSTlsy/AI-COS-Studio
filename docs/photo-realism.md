# 真人摄影方法 v2

本轮将仓库摄影方法应用到基准生成和后期创作，而不是继续生成脸模测试。代码由 `lib/photography-methods.mjs` 管理新增方法，`realismPrompt` 在原有 v1 基础之后追加 `photography-v2` 分阶段规则。两种后端共用已编译 Prompt；不依赖额外工具调用。

## 当前入口与自动应用范围

| 阶段 | 自动加入的摄影关系 | 可选入口 |
| --- | --- | --- |
| 基准 | 动漫妆造的实体化、五官体积与受光、非发光虹膜、景别对应的面部细节；主图姿态背景不变 | 摄影风格：自然面部与妆面成像、现场纪实成像 |
| 随机重拍 | 事件—视线—动作响应、前后景层级、固定世界空间光源；不自动糊脸 | 成像预设：上述两个新预设与原有四个并存 |
| 系列写真 | 共同曝光色彩、主辅参考职责、分镜与光照拓扑；不另抽故事 | 成像预设只补充，不覆盖主参考或企划 |
| 单项调整 | 按动作、服装、背景、比例、妆容、发型、镜头/光线或其他类别限定影响区域 | 分类建议：窗侧光、冷暖光、自然动作、妆面附着、发丝固定、实体衣料 |

Prompt 库的「真人摄影方法」卡片可筛出 8 个新增模块；每条可编辑、归档，展开来源查看案例与边界。新模块版本从 v1 开始，其 ID 的 v2 表示本次方法包代际，不是用户编辑次数。

旧的四个成像预设和已编辑、已归档素材均不覆盖。新增固定 ID 只做幂等补充。已存任务、草稿、版本和已准备网页交接不重新编译；新建基准或新创建/编译后期方案时才应用新版。失败重试复用已冻结输入，不自动升级 Prompt。完整 Prompt 中的版本标识与模块来源随现有快照保存。

## 使用

- 基准生成：在摄影风格中选择自然相机摄影、手机生活抓拍、弱光现场摄影或复古数码相机；也可保留原风格或无附加风格。基准构图、姿态和场景仍服从主图。
- 随机重拍、系列写真：在生成方案前选择可选成像预设，默认沿用方案。四个预设可在 Prompt 库中编辑或归档；批次冻结完整模块快照，后续修改库不影响重抽、返工、交接及归档版本。
- 真人基础规则随新编译 Prompt 加入，只细化肤质、材质、受力接触与光学可信度。单项调整仅作用于所选类别及必要影响区域，禁止全图美化。
- 冲突提示显示可能矛盾的原句，不修改、不拦截、不代表完整语义审查。当前覆盖单烛光与额外补光、皮肤标记、过度修饰、景深矛盾及脸部模糊；中文和英文否定表达做基础排除。
- 已归档预设不自动复活，已编辑预设不重置。新增模块按固定 ID 幂等补充。
- 网页重拍继续使用右下角草书“阿茶”，不复制第三方作者署名。

## 人工网页对照验收

保留[基准面部真人化与人工验收](baseline-face-realism.md)和可选 A/B 入口，不再将脸模测试标记为当前任务。新基准交接中的“基准面部 A/B”只移除/保留 `baseline-face-v1`，两份都保留其余摄影规则；其他阶段的真人质感 A/B 同时移除/保留完整 v1 基础与 v2 分阶段块。旧提示词只比较其原有 v1 规则；手改或不完整规则块不提供该对照。以下为可选人工流程，本轮不自动生图。

先完成代码测试再提醒用户。只需首先验证真人基础规则，不同时改变脸模、风格、动作、背景或画幅。

1. 用户选定一份已确认、获授权的角色参考或干净 COS 源图及其摄影方案。
2. 在新准备的网页交接中展开「真人质感 A/B 对比（可选）」，分别复制 A、B。A 仅移除新增真人规则，B 保留；其余文字、预设、参考图及顺序完全一致。A 不是完整旧版引擎，只测试基础规则。只有完整未手改的新增规则块才提供此入口，历史提示词不提供。
3. 使用两个独立的新 ChatGPT 图片会话，各上传同一组参考，一次生成一张。A、B 分开保存，不在 A 的生成结果上编辑 B。不自动提交，不自动重试。
4. 首轮仅两张。保留原文件、Prompt、生成时间和参考顺序；先供对比，不把 A 冒充 B 的配置归档进同一结果槽。用户把两张结果提供给 Codex 后再检查。
5. 对照同一显示尺寸，检查：脸部身份与角色设计、近远景肤质、妆容保留、发饰固定、手部接触、织物受力、光向与反光、非预期模糊或噪点。
6. 记录每项“改善／无明显变化／退化”及具体位置，由用户选择；不自动评分或选择。单对结果受随机性影响，不能证明稳定提升。如果存在退化，先反馈原因，由用户决定是否进行下一轮。

之后才分别测试四个成像预设；弱光预设须选已有弱光场景，复古预设不作为通用真实度增强。
